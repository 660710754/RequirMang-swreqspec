# Feature: อัปเดตสถานะ Order (Update Order Status)
Spec ID: SPEC-STAFF-ORDER-STATUS-001 | Source: SRS v0.1 ข้อ 3.8 (FR-STAFF-ORDER-STATUS) | Use case: UC-08
Owner: <ทีม/คน> | Status: Draft v2 | Updated: 2569-09-18
Depends on: SPEC-STAFF-ORDER-001, SPEC-ORDER-STATUS-001, SPEC-NOTIFICATION-001 | Reviewed by: -

## Goal
พนักงานร้านสามารถอัปเดตสถานะของ Order ตามขั้นตอนการเตรียมเครื่องดื่ม
เพื่อให้ข้อมูลสถานะของ Order เป็นปัจจุบันและให้ลูกค้าสามารถติดตามความคืบหน้าได้

## Scope

### In scope
- แสดงรายการ Order ให้พนักงานเลือก
- แสดงสถานะปัจจุบันของ Order
- ให้พนักงานเลือกสถานะใหม่
- ตรวจสอบความถูกต้องของสถานะ
- บันทึกสถานะใหม่
- เรียกใช้ UC-06 เมื่อสถานะเปลี่ยนเป็น “พร้อมรับสินค้า”

### Out of scope
- การสร้าง Order
- การชำระเงิน
- การส่งข้อความ LINE โดยตรง
- การจัดการบัญชี LINE
- การจัดการเมนู ราคา และโปรโมชั่น
- การดูรายงานยอดขายและสถิติ

## Constraints
- เฉพาะพนักงานที่มีสิทธิ์เท่านั้นที่สามารถอัปเดตสถานะ Order ได้
- Order ต้องมีอยู่ในระบบก่อนอัปเดตสถานะ
- ระบบต้องตรวจสอบความถูกต้องของสถานะก่อนบันทึก
- สถานะ Order เป็นลำดับไปทางเดียว: รอรับ Order → กำลังเตรียม → พร้อมรับสินค้า → รับสินค้าแล้ว
- พนักงานไม่สามารถเปลี่ยนสถานะย้อนกลับได้
- เมื่อสถานะเปลี่ยนเป็น “พร้อมรับสินค้า” ระบบต้องเรียกใช้ UC-06
- หากการแจ้งเตือนผ่าน LINE ล้มเหลว ต้องคงสถานะ Order ไว้และไม่ retry อัตโนมัติทันที

## Requirements
- FR-24
  ระบบต้องสามารถให้พนักงานเลือก Order และดูสถานะปัจจุบันได้

- FR-25
  ระบบต้องสามารถให้พนักงานเลือกสถานะใหม่ของ Order ได้
  การเปลี่ยนสถานะต้องเป็นไปตามลำดับที่กำหนด: รอรับ Order → กำลังเตรียม → พร้อมรับสินค้า → รับสินค้าแล้ว

- FR-26
  ระบบต้องตรวจสอบความถูกต้องของสถานะก่อนบันทึก
  สถานะที่เลือกต้องเป็นสถานะถัดไปในลำดับที่กำหนด และห้ามข้ามขั้น
  ไม่อนุญาตให้พนักงานเปลี่ยนสถานะย้อนกลับ

- FR-27
  ระบบต้องบันทึกสถานะใหม่ของ Order เมื่อข้อมูลถูกต้อง
  การบันทึกสถานะต้องเกิดทันทีโดยไม่ต้องยืนยันซ้ำ

- FR-28
  เมื่อสถานะใหม่เป็น “พร้อมรับสินค้า” ระบบต้องเรียกใช้ UC-06 เพื่อดำเนินการแจ้งเตือนลูกค้าผ่าน LINE
  สถานะ Order จะต้องอัปเดตให้ลูกค้าเห็นแบบ Real-time

### Alternative Flow Requirement

- FR-28 / UC-08 Alternative Flow 6a
  หากสถานะใหม่คือ “พร้อมรับสินค้า” ระบบต้องเรียกใช้ UC-06 เพื่อดำเนินการตรวจสอบ LINE User ID และส่งการแจ้งเตือน

### Exception Flow Requirement

- UC-08 Exception Flow 5a
  หากไม่สามารถอัปเดตสถานะได้ ระบบต้องแจ้งเตือนพนักงานและคงสถานะเดิมของ Order

- UC-08 Exception Flow 6b
  หากสถานะเปลี่ยนเป็น “พร้อมรับสินค้า” แต่การแจ้งเตือนผ่าน LINE ไม่สำเร็จ ระบบต้องคงสถานะ Order เป็น “พร้อมรับสินค้า” และบันทึกผลการแจ้งเตือนล้มเหลว

## Quality Requirements
- NFR-REL-01
  ระบบต้องไม่ทำให้ข้อมูลสถานะ Order ไม่สอดคล้องกันเมื่อเกิดข้อผิดพลาดระหว่างการอัปเดต

- NFR-SEC-01
  เฉพาะพนักงานที่ได้รับสิทธิ์เท่านั้นที่สามารถอัปเดตสถานะ Order ได้

## Acceptance Criteria

- [ ] AC-STATUS-01 (FR-24 / FR-25 / FR-26 / FR-27)

  Given พนักงานมีสิทธิ์และมี Order อยู่ในระบบ
  When พนักงานเลือกสถานะใหม่และยืนยัน
  Then ระบบตรวจสอบและบันทึกสถานะใหม่ของ Order ได้สำเร็จ

- [ ] AC-STATUS-02 (FR-27)

  Given พนักงานอัปเดตสถานะสำเร็จ
  When ลูกค้าเปิดดู Order
  Then ลูกค้าสามารถเห็นสถานะล่าสุดของ Order ได้

- [ ] AC-STATUS-03 (FR-28 / UC-08 Alternative Flow 6a)

  Given พนักงานเลือกสถานะใหม่เป็น “พร้อมรับสินค้า”
  When ระบบบันทึกสถานะสำเร็จ
  Then ระบบเรียกใช้ UC-06 เพื่อดำเนินการแจ้งเตือนลูกค้าผ่าน LINE

- [ ] AC-STATUS-04 (UC-08 Exception Flow 5a)

  Given พนักงานพยายามอัปเดตสถานะ Order
  When ระบบไม่สามารถบันทึกสถานะได้
  Then ระบบแจ้งเตือนพนักงานและคงสถานะเดิมของ Order

- [ ] AC-STATUS-05 (UC-08 Exception Flow 6b)

  Given Order เปลี่ยนสถานะเป็น “พร้อมรับสินค้า”
  When การแจ้งเตือนผ่าน LINE ไม่สำเร็จ
  Then Order ยังคงมีสถานะ “พร้อมรับสินค้า” และระบบบันทึกผลการแจ้งเตือนล้มเหลว

## Assumptions and Open Questions

### Assumptions
- พนักงานมีสิทธิ์ในการอัปเดตสถานะ Order
- สถานะ Order ที่ระบบรองรับมีลำดับตามกระบวนการของร้าน: รอรับ Order → กำลังเตรียม → พร้อมรับสินค้า → รับสินค้าแล้ว
- UC-06 เป็นผู้รับผิดชอบการแจ้งเตือนผ่าน LINE
- การแจ้งเตือนผ่าน LINE ไม่ใช่เงื่อนไขที่ทำให้สถานะ Order เปลี่ยนหรือย้อนกลับ
- ไม่อนุญาตให้พนักงานเปลี่ยนสถานะย้อนกลับ
- เมื่อการแจ้งเตือนผ่าน LINE ไม่สำเร็จ ระบบจะคงสถานะไว้และไม่ retry อัตโนมัติทันที

### Open Questions
- สถานะ Order ที่ระบบต้องรองรับทั้งหมดมีอะไรบ้าง
- มีสถานะอื่นนอกเหนือจากลำดับพื้นฐานหรือไม่
- หากพนักงานเปลี่ยนสถานะผิด จะมีการยืนยันก่อนบันทึกหรือไม่
