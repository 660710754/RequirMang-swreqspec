# แผนงานสำหรับ Feature: ดูเมนูและโปรโมชั่น (Menu & Promotion)

## 1. สรุปแนวทาง
- ฟีเจอร์นี้จะสร้างหน้าเมนูและโปรโมชั่นให้ผู้ใช้ทั่วไปดูรายการเครื่องดื่มที่ร้านเปิดขาย พร้อมชื่อ ราคา รายละเอียด สถานะ และโปรโมชั่นที่กำลังใช้งานอยู่ ตาม FR-01, FR-02, FR-03, FR-05 และ AC-MENU-01 ถึง AC-MENU-07
- กลุ่มผู้ใช้หลักคือ นักศึกษา / ลูกค้า ที่เป็นผู้ใช้ทั่วไปของระบบเมนูและโปรโมชั่นเดียวกัน ตาม Goal และ Assumptions ASM-01 ถึง ASM-05
- ระบบจะให้แสดงเมนูที่เปิดขายและแสดงสถานะ “หมด” สำหรับเมนูที่หมดสต็อก พร้อมแสดงข้อความ “ไม่พบเมนู” เมื่อคำค้นหาไม่ตรง และแสดงข้อความ “ไม่สามารถโหลดข้อมูลได้” เมื่อโหลดข้อมูลเมนูล้มเหลว ตาม FR-02, FR-03, UC-01 Exception Flow 2a และ AC-MENU-03, AC-MENU-05
- หน้าเมนูและโปรโมชั่นจะใช้หน้าเดียวกัน และจัดเรียงสินค้าที่มีโปรโมชั่นไว้ด้านบนสุด หากไม่มีโปรโมชั่นที่กำลังใช้งานอยู่ ระบบจะไม่แสดงส่วนโปรโมชั่น แต่ยังคงแสดงเฉพาะเมนูเปิดขายเท่านั้น ตาม FR-05 และ AC-MENU-04
- แผนนี้จะไม่สร้างฟังก์ชันนอก scope เช่น การสมัครสมาชิก/เข้าสู่ระบบ การสั่งซื้อออนไลน์ การชำระเงิน การตรวจสอบสถานะ Order และการจัดการเมนู/ราคา/โปรโมชั่น เพราะถูกกำหนดไว้ชัดเจนใน Out of scope

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าเมนูและโปรโมชั่น | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้แสดงรายการเมนู, search, status badge, และ section โปรโมชั่นในหน้าเดียวกัน |
| Python FastAPI สำหรับ API ดึงข้อมูลเมนูและโปรโมชั่น | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้คืนข้อมูลเมนูที่เปิดขายพร้อมโปรโมชั่นที่กำลังใช้งานอยู่ |
| ฐานข้อมูลเชิงสัมพันธ์ (เช่น PostgreSQL) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บเมนู, สถานะสินค้า, และข้อมูลโปรโมชั่นที่ใช้งานอยู่ |
| Search service สำหรับ partial match ไม่แยกตัวพิมพ์เล็ก/ใหญ่ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สำหรับ FR-03 และ ASM-01 |
| Error state UI สำหรับ “ไม่สามารถโหลดข้อมูลได้” | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้แสดงข้อความและปุ่ม “ลองใหม่” ตาม UC-01 Exception Flow 2a |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ FR / NFR |
|---|---|---|
| MenuItem | `menu_id`, `name`, `price`, `description`, `status`, `is_active`, `updated_at` | รองรับ FR-01, FR-02, AC-MENU-01, AC-MENU-02, AC-MENU-03 |
| Promotion | `promotion_id`, `title`, `status`, `start_at`, `end_at`, `priority` | รองรับ FR-05, AC-MENU-04 |
| MenuPromotionLink | `menu_id`, `promotion_id`, `display_order` | รองรับ FR-05, ASM-03 |
| SearchRequest | `keyword` | รองรับ FR-03, AC-MENU-03 |
| MenuLoadResult | `items[]`, `promotion[]`, `status`, `error_message`, `retry_action` | รองรับ UC-01 Exception Flow 2a, AC-MENU-05 |

หมายเหตุโมเดลข้อมูล:
- จะไม่มีฟิลด์สำหรับข้อมูลสมาชิก/บัญชีผู้ใช้, การสั่งซื้อ, การชำระเงิน, หรือ status ของ Order เพราะฟีเจอร์นี้อยู่ใน Out of scope
- `MenuItem.status` จะใช้ค่าที่สอดคล้องกับ ASM-02 เช่น `open` และ `out_of_stock`
- `Promotion.status` จะคัดกรองเฉพาะโปรโมชั่นที่กำลังใช้งานอยู่ตาม FR-05 และ ASM-04

## 4. API / หน้าจอ

- `GET /api/menu` — Input: ไม่มีหรือ `search` keyword; Output: รายการเมนูที่เปิดขายพร้อมสถานะและราคา — รองรับ FR-01, FR-02, FR-03, AC-MENU-01, AC-MENU-02, AC-MENU-03
- `GET /api/promotions/active` — Input: ไม่มี; Output: รายการโปรโมชั่นที่กำลังใช้งานอยู่ — รองรับ FR-05, AC-MENU-04
- `GET /menu` — หน้าเมนูและโปรโมชั่นรวมในหน้าเดียว, แสดง section โปรโมชั่นและรายการเมนู — รองรับ FR-01, FR-02, FR-05, AC-MENU-01, AC-MENU-04
- `POST /api/menu/search` — Input: keyword; Output: รายการที่ตรงกับคำค้นแบบ partial และข้อความ “ไม่พบเมนู” เมื่อไม่มีผลลัพธ์ — รองรับ FR-03, AC-MENU-03
- `GET /api/menu/error` หรือ error state ใน UI — Output: ข้อความ “ไม่สามารถโหลดข้อมูลได้” พร้อมปุ่ม “ลองใหม่” — รองรับ UC-01 Exception Flow 2a, AC-MENU-05

## 7. ลำดับงาน

1. กำหนด schema ของเมนูและโปรโมชั่น: `MenuItem`, `Promotion`, `MenuPromotionLink` พร้อม status และ priority ตาม FR-01, FR-02, FR-05
2. สร้างหน้าเมนูและโปรโมชั่นรวมในหน้าเดียว พร้อม section โปรโมชั่นและรายการเมนูที่เปิดขายตาม FR-01, FR-05 และ AC-MENU-01, AC-MENU-04
3. สร้าง API ดึงข้อมูลเมนูและโปรโมชั่นที่กำลังใช้งานอยู่ พร้อม filter ตาม status และ order โดยสินค้าที่มีโปรโมชั่นไว้ด้านบนสุด ตาม FR-01, FR-02, FR-05, ASM-03, ASM-04
4. สร้าง logic สำหรับ partial search แบบไม่แยกตัวพิมพ์เล็ก/ใหญ่ และข้อความ “ไม่พบเมนู” เมื่อไม่พบผลลัพธ์ตาม FR-03 และ AC-MENU-03
5. สร้าง UI state สำหรับเมนูหมดสต็อกแสดง “หมด” และสถานะเมนูเปิดขายสามารถกดสั่งได้ ตาม FR-02 และ AC-MENU-02
6. สร้าง error state สำหรับกรณีโหลดข้อมูลเมนูล้มเหลว โดยแสดง “ไม่สามารถโหลดข้อมูลได้” พร้อมปุ่ม “ลองใหม่” ตาม UC-01 Exception Flow 2a และ AC-MENU-05
7. ทดสอบประสิทธิภาพและ usability ตาม NFR-22 และ NFR-26, รวมถึง AC-MENU-06 และ AC-MENU-07
